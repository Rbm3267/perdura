PERDURA / DESIGN BRIEF v0.1 2026-06-09 STATUS: PHASE 1 RUNNING

Perdura
The mind that outlives its models.

A persistent knowledge graph that hires and fires LLMs based on what it has learned about them — spending money only where it disagrees with itself.

Overview

The inversion

Conventional multi-agent systems treat agents as persistent and memory as incidental. Perdura inverts this: the memory is the system, and LLMs are interchangeable workers that board, contribute, and disembark.

The "mind" is a living knowledge graph — claims, evidence, open questions, decisions, and rejected paths, all typed, attributed, and confidence-scored. Because no working state ever lives inside a model, any model can be swapped mid-task with zero loss. The mind survives every model that ever powered it.

There is no limit to how many models can serve the graph over its lifetime. The briefing each worker receives is bounded regardless of how many came before it.

Claim 01

Inverted persistence

The graph is the system of record. Models are stateless, commodity labor — swappable at any station because the state rides the train, not the worker.

Claim 02

Epistemic track records

Every node is attributed. Over time the graph learns which models are reliable in which domains. The memory evaluates its workers.

Claim 03

Contention-driven economics

Cheap local models are the default labor force. Frontier and specialist models are summoned only where contradiction density rises.

Architecture

The line and its stations

The memory is the line — continuous, persistent, always moving forward. Models are stations: the train stops, a worker boards with a bounded briefing, contributes a graph delta, and the train moves on without it.

The memory line never stops; workers do. Solid stations run today (Phase 1, round-robin). The specialist station opens when the router ships (Phase 3) — its boarding trigger is the contention metric, cost budgets, or a domain-tag match.
knowledge graph

Typed nodes and edges; append-mostly. Nodes are superseded, never deleted, preserving the temporal record of how the mind changed. This is the living mind map.

conductor

Deterministic code. Assembles bounded briefings (2-hop neighborhood of the most-contended open question), schema-validates incoming deltas, stamps attribution, merges, and recomputes contention. No LLM judgment in the merge path.

workers

Any LLM behind a uniform interface. A worker sees a briefing — never a transcript, never authorship of prior nodes — and returns a strict-JSON delta. It holds zero state worth preserving.

router

Phase 3. A model registry (domain tags, cost, latency, accumulated track record) that matches open questions to workers and escalates when a subgraph disagrees with itself.

retrieval index

Phase 1.5. Nodes embedded into ChromaDB; briefings assembled by hybrid BM25 + dense search expanded through graph traversal — the forge-rag pattern applied to the mind itself.

Graph schema

Node typeMeaning
questionAn open question driving work. status: open / resolved
claimA position or assertion, confidence-scored 0–1
evidenceSupporting material, source-attributed
decisionA resolved choice, linked to the claims that won
rejectedAn abandoned path and the reason — prevents re-litigating
Edge typeMeaning
supportsclaim / evidence → claim
contradictsclaim ↔ claim — drives the contention metric, and therefore the spend
refinesclaim → claim (a sharper version)
answersclaim → question
depends_onclaim / decision → claim / decision

Contention for a subgraph S = confidence-weighted contradicts edges ÷ claim nodes in S. Rising contention is the signal to summon stronger or specialist workers.

Worker lifecycle

Board

Briefing issued

Conductor selects the most-contended open question and assembles a token-capped subgraph briefing.

Contribute

Delta returned

Strict JSON only: new nodes, new edges, supersedes, resolved questions. No prose.

Merge

Conductor validates

Schema check, ID assignment, attribution stamp, contention recompute. Malformed deltas are rejected and logged.

Disembark

Worker released

Nothing is lost — the worker never knew anything the graph didn't.

Requirements

What the system must do

Functional

FR-01
Persistent typed graph. Store typed nodes and edges with attribution, confidence, domain tags, and timestamps; persist across sessions independent of any model.P1 ✓
FR-02
Supersede, never delete. Stale nodes are marked superseded with a pointer to their replacement, preserving the full temporal record.P1 ✓
FR-03
Bounded briefings. Worker context is assembled from the open question's 2-hop neighborhood under a fixed token/char budget, regardless of total graph size or worker count.P1 ✓
FR-04
Strict delta contract. Workers return JSON-only deltas (nodes, edges, supersedes, question resolutions). The conductor schema-validates and rejects non-conforming output, logging the failure.P1 ✓
FR-05
Deterministic merge. Validation, ID assignment, attribution, and contention recompute are pure code — no LLM judgment in the merge path.P1 ✓
FR-06
Contention metric. Compute confidence-weighted contradiction density per subgraph; use it to prioritize which open question is worked next.P1 ✓
FR-07
Anonymous briefings. Workers see node content and confidence but never authorship, countering anchoring and sycophancy toward frontier-model output.P1 ✓
FR-08
Uniform worker interface. Any model — hosted or local, via OpenAI-compatible or native SDK — participates through the same briefing-in / delta-out contract.P1 ✓
FR-09
Merge ledger. Log per-worker accepted/rejected/error counts from turn one — the raw material for track records.P1 ✓
FR-10
Hybrid retrieval. Embed nodes; assemble briefings via BM25 + dense search expanded through graph traversal.P1.5
FR-11
Track-record analytics. Per-model, per-domain reliability computed from how a model's claims fare: supported, contradicted, superseded, or promoted to decisions.P2
FR-12
Epistemic router. Registry of models (tags, cost, latency, track record); contention-, budget-, and domain-triggered boarding and escalation.P3

Non-functional

NFR-01
Unbounded worker count. Cost and context per turn stay flat no matter how many models have ever served the graph.
NFR-02
Local-first. The full loop runs on a single M4 Mac Mini with a local model and no cloud dependency; hosted models are an enhancement, not a requirement.
NFR-03
Model-agnostic. No worker-specific logic outside its thin adapter; swapping a model requires zero changes to graph, conductor, or schema.
NFR-04
Auditable. Every node answers who said this, when, with what confidence, and what replaced it. The mind's history is inspectable end to end.
NFR-05
Resilient to bad workers. A malformed or low-quality delta can be rejected without corrupting state; rejection itself becomes track-record signal.
NFR-06
Cost-proportional to disagreement. Steady-state spend trends toward local-model cost; frontier spend concentrates where contention is high.
Roadmap

Phases

PHASE 1

Graph memory + delta extraction with Claude, Gemini, and local Qwen. JSON persistence, round-robin boarding, CLI. Proves the inverted-persistence loop end to end. Built and verified.

PHASE 1.5

Retrieval layer (ChromaDB, hybrid search + graph expansion) and the living mind-map visualization — force-directed graph, this visual language.

PHASE 2

Attribution analytics: per-model, per-domain track records computed from node outcomes. The memory starts judging its workers.

PHASE 3

The epistemic router: registry, contention-driven escalation, cost budgets, specialist summoning. Claims 02 and 03 proven with accumulated data.
